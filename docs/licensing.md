# 桌面授权接入

派生应用使用同一个外部 Grantmint v2 授权服务。管理员在该服务登记应用和客户许可，现场用户用许可证 UUID 和激活秘密激活本机。

## 产品配置

在打包前填写 [licensing.json](../src-tauri/licensing.json) 并重新构建客户端。只需要可随应用发布的配置：

| 字段 | 值 |
| --- | --- |
| serverUrl | Grantmint gateway 的 HTTPS 基础地址，不含查询、凭据或片段。开发构建支持本机回环 HTTP 测试服务。 |
| productId | 在 Grantmint 登记的应用 UUID，小写且带连字符。 |
| trustedKeys | 以签发公钥的 kid 为键、原始 32 字节 Ed25519 公钥的标准 Base64 为值。轮换期间保留仍有有效证书的旧公钥。 |

初始配置为空，授权页显示“待配置”。服务端签发私钥和客户激活秘密仅用于各自的签发、激活流程。每个产品使用独立应用 UUID、本地应用标识和数据目录。

## 生命周期

1. 在授权页输入许可证 UUID 和 64 位十六进制激活秘密。客户端取得一次性挑战，以本机设备私钥完成挑战，再使用受信公钥校验证书和签名时间回执。证书持久化成功后向服务确认领取。
2. 激活成功后可断网和重启。应用到期前七天提醒，到期后提供续期入口。应用页面和业务任务在上述状态下均可照常使用。
3. 管理员在服务端延期后，点击“更新授权”。只有完整校验并保存的新证书才替换旧证书。遇到网络错误可稍后重试。
4. 设备密钥和证书在当前产品及运行环境的应用数据目录下保存于 licensing 子目录，使用当前 Windows 用户的 DPAPI 保护。它们独立于项目目录。更换主板、重装系统或更换 Windows 账号后，应联系授权管理员处理设备绑定。
5. 时钟异常时先核对 Windows 系统时间；设备绑定不匹配或受保护文件损坏时，按状态提示联系管理员。应用使用安全存储内已接受的版本和时间记录检查旧证书回滚及明显时钟回拨。设备指纹只发送摘要。

## 首次初始化与旧版数据

首次创建的设备身份、时间记录和初始证书状态经 DPAPI 保护，先写入同一授权目录的暂存目录，再一次性发布到 `licensing/current/`。提交前退出或写入失败时，下次启动会重试。提交成功后始终使用已发布的身份。

旧版已存在的平铺文件继续原地使用。若旧版目录残缺，客户端无法区分首次中断与已激活记录损坏，会保留原文件并提示恢复。请保留整个目录，由授权管理员核对对应设备和许可证，使用同一 Windows 用户的完整、最新一致备份恢复，或通过服务端办理重新绑定。仅替换设备密钥或证书可能造成身份或版本不匹配。
