# 通用桌面框架设计提案

状态：讨论稿，尚未实现。

首版已确定内置项目管理，并支持在同一应用进程和窗口中切换项目。切换行为见下文“进程内切换规则”。

## 目标与定位

从 GlueSight 提取适合新桌面项目的应用壳和基础能力。首版建议沿用 Tauri 2、React、TypeScript 与 qing-steel。Windows 是桌面模板首版唯一的验收平台。

模板生成的项目拥有独立源码；它不会自动接收模板后续修复。第一阶段按单仓库模块组织，等多个产品出现稳定的共享需求后，再考虑发布共享包。

## 建议首版范围

| 模块 | 建议能力 | 抽取边界 |
| --- | --- | --- |
| 应用外壳 | 自绘标题栏、窗口控制、可折叠分组导航、页面容器、标题栏操作插槽、错误边界 | 保留基本视觉与交互，品牌和导航由应用配置提供 |
| 基础 UI | 浅色、深色和跟随系统三种主题模式，表单、卡片、弹窗、通知、加载与空状态 | 沿用 qing-steel，窗口标题栏与各页面共用主题 |
| 应用配置 | 类型化设置、版本字段、校验、持久化、损坏文件保留与错误反馈 | 新建通用设置模型，不沿用检测设置；业务配置归业务模块 |
| 项目管理（必备） | 项目列表、新建、重命名、复制、删除、切换、导入导出、重开上次项目 | 框架管理项目身份、目录与生命周期；业务模块定义项目内容 |
| 软件授权（必备） | 接入统一授权服务，完成设备激活、离线验签、到期提醒与续期 | 每个派生产品对应授权服务中的一个应用，各项目共享本机该产品的授权状态 |
| MCP 接入 | 固定连接入口、服务启停与通用配置 | 派生应用显式注册业务工具并负责其行为 |
| 在线更新 | 派生产品配置更新源与更新包验签公钥 | 更新包和发布节奏由各产品维护 |
| 运行日志 | 使用 `tracing` 写入纯文本文件，从“关于”打开当前日志 | 应用统一轮转，仅按保留天数清理归档 |
| 桌面基础 | 应用数据路径、开发与正式环境隔离、数据目录独占、启动就绪通知 | 应用标识决定存储边界；新产品不得访问 GlueSight 数据目录 |
| 关于 | 应用名、版本、提交、构建时间、日志及数据位置 | 应用身份集中配置 |
| 工程入口 | 前端预览、桌面开发、定向测试、Windows 打包与基础 CI | 不依赖现场 SDK、算法引擎或本机绝对路径 |

默认页面建议包括项目、欢迎/示例、设置和关于。侧栏保留当前项目与切换入口。示例页展示如何注册一个业务页面，不接真实业务。

外观设置保存用户选择的模式。首次启动建议使用“跟随系统”，按 Windows 当前应用主题显示，并在系统主题变化时即时更新。手动选择浅色或深色后，始终使用选定外观。切换项目或重启后沿用已保存的模式。

应用设置、项目清单和最近打开的项目使用 JSON 文件保存。框架管理这些文件和项目目录。需要记录查询或事务处理的派生应用可自行引入 SQLite，由业务模块负责表结构和版本迁移。

## 项目管理的通用边界

项目是一个独立的数据与配置空间，适用于工程、文档集合或业务方案，不预设相机、配方等对象。

- 应用级：应用身份、外观偏好、最近项目、当前项目选择与日志保留策略。
- 项目级：稳定的项目 ID、名称、描述、格式版本，以及业务模块自己的配置和资源。重命名不改变项目 ID。
- 生命周期：框架负责打开、关闭和切换项目。用户决定何时切换，业务模块自行管理编辑和任务。
- 空项目：无需业务模块即可创建和打开；未选择项目时，项目页面仍可用，项目相关业务入口显示明确的空状态。

### 项目复制与导入导出

导出生成项目包，可用于迁移或备份。包内清单记录项目名称和导出时间，随包保存业务模块声明的可迁移内容。应用授权、本机路径、凭据、缓存和运行日志均排除在包外。

| 操作 | 项目身份与结果 |
| --- | --- |
| 复制项目 | 分配新 ID，原项目与副本可以独立修改。 |
| 导入为新项目 | 分配新 ID，即使本机已有原项目，也可并排保留两个版本。 |

导入时先校验包版本、路径边界与内容完整性，全部成功后才把新项目加入项目列表。验收时连续导入同一份备份两次，验证两个副本可独立编辑；导入失败时项目列表和已有项目内容保持原状。

### 进程内切换规则

用户选择项目 B 时，框架直接在当前窗口打开 B。B 打开成功后更新当前项目、侧栏与下次启动的项目。若 B 无法打开，显示具体原因并继续使用 A。

切换由用户主动发起，无需业务模块批准。草稿和进行中的任务均不触发框架确认、等待或取消。业务模块自行维持操作的数据归属，例如对 A 发起的导出在切换到 B 后仍读取 A 的数据。

## 统一软件授权

授权服务及其网页管理后台由独立仓库维护，供多个产品共用。管理员账号和登录功能归该后台。管理员为每个产品登记一个应用，并在该应用下管理客户许可证和设备绑定。

模板交付桌面授权客户端、配置样例和接入说明。派生产品配置服务地址、对应应用的 UUID 和验签公钥即可接入。现场用户使用激活凭据为本机办理授权。应用 UUID 标识产品，同一产品的各安装实例共用该 UUID，各设备分别激活。新应用未配置服务时正常启动，授权页显示“待配置”。

首版纳入应用级软件授权。协议建议沿用已做过 Windows 本地验收的 Grantmint v2 设备挑战与离线证书。GlueSight 的早期设计记录了业务规则，后续草稿实现给出了实际使用的 SDK 和协议。服务端语言可以独立选择，协议和测试向量是客户端的接入依据。[早期设计](https://github.com/liangyuR/ly-gluesight/blob/432119ad1e88041ee33cce4b06caf2e6308f5e5a/docs/architecture/software-licensing.md) · [v2 实现参考](https://github.com/liangyuR/ly-gluesight/pull/314)

- **统一管理。** 管理员按产品和客户签发激活凭据、设置到期日期、查看设备绑定、延期或处理换机，变更留审计记录。一份授权绑定一个产品和一台设备。离线设备上已签发的有效证书可以用至原截止时间，后台操作的生效时间应对管理员可见。
- **密钥归属。** 签发私钥由服务端保管。各应用配置自己的 UUID、服务地址和受信公钥，按密钥标识支持轮换。设备私钥由客户端在本机生成，Windows 使用当前用户的 DPAPI 保护私钥、证书与校验状态。模板只提供配置样例，激活凭据、设备私钥和签发私钥均排除在日志、诊断包和项目导出之外。
- **激活与续期。** 用户输入激活凭据，客户端完成设备挑战，核验签名、产品、设备、期限与证书版本后保存。有效证书支持断网和重启。服务端延期后，用户点击“更新授权”领取新证书，领取失败时继续按原证书判断。
- **到期判定。** 到期前七天提醒，到期时刻为管理员所选停用日的北京时间零点。Rust 在启动、运行中和休眠唤醒时检查授权，将验签结果和有效期提供给应用界面。
- **项目切换。** 授权属于本机产品。切换、复制、导入项目都沿用本机的授权判断。项目在另一台设备打开时，使用目标设备自己的许可证。

### 到期提示与续期

启动时已到期、运行中到期或唤醒时发现到期，应用在当前界面显示非阻塞的“授权已到期”提示，提供“更新授权”入口。用户可继续使用当前页面，也可自行打开授权页。验签、提醒和续期由授权模块完成，任务的启动与执行由业务模块负责。

授权页显示产品、授权状态和证书中的到期时间。未激活时提供激活入口。证书损坏、产品或设备不匹配时显示具体原因和相应处理方式。以上状态均只影响授权提示，业务照常运行。新证书核验并保存后刷新状态和提示，更新失败时保留原状态并允许重试。

验收时覆盖未配置、未激活、证书异常、到期前七天提醒、到期瞬间、启动已过期、休眠跨越到期时间及续期成功和失败。检查各状态均能进入业务页面、已启动的任务正常完成、新操作可照常发起。用隔离的 Windows 实例验证跨产品或跨设备证书被判为无效、离线重启及项目切换保留授权状态，以及时钟回拨时的判断。

## MCP 接入与在线更新

框架提供固定的 MCP 接入入口和一处服务配置。建议由产品配置启用状态、本机监听地址和端口，设置页展示实际连接地址和运行状态。模板的工具清单初始为空，注册工具后由派生应用实现参数校验、权限判断和实际操作。验收时分别验证空清单和注册一个示例工具后的发现与调用。

在线更新使用产品级配置。建议由维护者配置启用状态、HTTPS 更新源和更新包验签公钥。公钥与软件授权签发密钥分别管理。桌面端提供检查更新入口，展示可用版本并验证下载的更新包。建议默认自动检查、由用户决定何时安装和重启。验收覆盖未配置更新源、已有最新版本、发现新版、服务不可达及更新包验签失败。

## 从现有代码抽取时的关键处理

- `src/layout/WindowFrame.tsx` 保留窗口行为，删除在线检测页面特判与 PLC、维护模式、引擎状态依赖。
- `src/layout/TitlebarContent.tsx` 的 details/actions 插槽可沿用；导航从 `Sidebar.tsx`、`nav.ts` 拆出业务入口，项目切换器保留并改为依赖通用项目模块。
- `src/pages/ProjectsPage.tsx`、`src/features/project/` 与 Rust `project/` 是项目管理的抽取入口；保留管理交互，将配方、相机、检测历史和资源引用裁剪替换为业务模块明确声明的项目内容。
- `src/App.tsx` 移除配方 `WorkspaceProvider`。`styles.css` 只提取布局与公共样式，避免带入业务选择器。
- `src/pages/SettingsPage.tsx` 借用布局和反馈方式；`src-tauri/src/settings.rs` 的 CycleSettings 是生产配置，不适合作为通用配置模型。
- 业务模块直接调用 `tracing`。应用启动时统一配置 `tracing-subscriber`，日志文件使用带时间、级别和消息的纯文本格式，关闭文件输出的 ANSI 颜色码。跨 Windows 本地日期或单文件达到 10 MiB 时换新文件。
- 日志归档默认保留 180 天，按季度留存可设为 90 天，最长 365 天。天数按 Windows 本地自然日计算，含今天。
- 应用启动或日志轮转时，按 Windows 本地日期，仅删除本应用已超出保留期的归档文件。同一天产生的所有分卷按同一日期清理。保留期内的归档、当前写入文件和目录中的其他文件均保留。
- “关于”页提供“打开当前日志”。点击时由桌面端定位当前写入的文件，通过 Windows 文本文件关联打开。文件使用 `.txt` 扩展名，便于查看、搜索和直接分享。打开失败时显示文件路径和错误原因。
- `src-tauri/src/fsio.rs` 和 `instance.rs` 可作为配置落盘、损坏备份与目录独占的参考；保存失败、并发保存和重启释放锁需定向验证。

## 模块组织建议

```text
src/
  app/                 应用身份、路由、导航与模块装配
  layout/              窗口、侧栏、页面容器与插槽
  features/
    projects/          项目管理、当前项目上下文与切换入口
    settings/          通用设置
    about/             应用信息
    example/           可移除的业务页面示例
  lib/                 桌面调用、事件与时间工具
  styles/              公共主题及布局
src-tauri/src/
  app_info.rs          版本与构建信息
  config.rs            配置加载、校验和保存
  projects/            项目清单、生命周期、复制与导入导出
  logging/             日志初始化、轮转与当前文件定位
  paths.rs             应用目录与环境隔离
  instance.rs          数据目录独占
docs/                  设计、契约与接入说明
scripts/               初始化、开发与打包
```

扩展先使用显式模块注册：页面、导航、设置区块和 React 插槽。Rust 命令显式注册。无需首版引入动态插件加载、通用依赖注入容器或独立插件协议。

业务模块依赖基础能力；基础能力不导入业务模块。桌面命令和事件通过统一基础层暴露，浏览器预览明确呈现后端不可用状态。

## 建议暂不进入基础模板

相机、PLC、lyFlow、配方与示教、检测历史、生产模拟器不属于通用范围。

后台任务及其管理界面由派生应用按业务需要实现。


## 实施顺序与验收建议

1. 抽取可运行 UI 壳：无业务模块仍能启动，窗口控制、导航折叠、错误隔离和预览状态可用。
2. 打通设置与日志。验证设置重启后保留，保存失败或并发保存时原配置完整。在 Windows 上点击“打开当前日志”，核对默认编辑器打开的文件包含刚写入的可读文本，轮转后再次点击能打开新文件。验收归档清理时，用保留窗口首日和前一日各自的多个分卷核对日期边界，确认仅前一日的分卷被清理，并核对保留期配置的年度上限。
3. 验证项目管理。在 A 有未保存编辑和进行中的导出时选择 B，确认切换直接生效，A 的导出仍使用 A 的数据。B 打开失败时仍显示 A。另验证空项目可打开，复制与导入生成独立身份，无效导入和删除操作保持其他项目完整。
4. 完成模板初始化：名称、图标、包名、应用标识和数据目录可替换，两个生成应用互不读写对方数据。
5. 验证 Windows 开发与安装链路：依赖可从干净环境恢复，启动无需生产设备与算法运行库。
6. 在应用运行时切换 Windows 的浅色和深色设置，核对“跟随系统”即时生效，手动模式保持所选外观。重启后检查模式选择，并在两种外观下检查自绘标题栏、弹窗和授权页的文字与操作按钮是否清晰可读。

每个回归测试对应上述具体契约，实施前再列出实际用例。当前仓库只有文档，不声明运行、测试或打包通过。
