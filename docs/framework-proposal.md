# 通用桌面框架设计提案

状态：讨论稿，尚未实现。

## 目标与定位

从 GlueSight 提取适合新桌面项目的应用壳和基础能力。第一版建议保留 Tauri 2、React、TypeScript 与 qing-steel，优先验证 Windows。后续是否正式支持 macOS、Linux，需要单独确定并验证。

模板生成的项目拥有独立源码；它不会自动接收模板后续修复。第一阶段按单仓库模块组织，等多个产品出现稳定的共享需求后，再考虑发布共享包。

## 建议首版范围

| 模块 | 建议能力 | 抽取边界 |
| --- | --- | --- |
| 应用外壳 | 自绘标题栏、窗口控制、可折叠分组导航、页面容器、标题栏操作插槽、错误边界 | 保留基本视觉与交互，品牌和导航由应用配置提供 |
| 基础 UI | 现有深色风格、表单、卡片、弹窗、通知、加载与空状态 | 沿用 qing-steel；浅色及跟随系统主题尚需验证，不能当作已有能力 |
| 应用配置 | 类型化设置、版本字段、校验、持久化、损坏文件保留与错误反馈 | 新建通用设置模型，不沿用检测设置；业务配置归业务模块 |
| 日志 | 结构化日志、级别/时间/关键词筛选、分页、实时跟随、滚动与容量限制 | 移除工件、配方、相机等专有字段，以通用上下文扩展 |
| 日志导出 | 导出选定范围日志、版本和构建信息 | 配置导出采用允许字段清单；诊断包不包含业务数据 |
| 桌面基础 | 应用数据路径、开发与正式环境隔离、数据目录独占、启动就绪通知 | 应用标识决定存储边界；新产品不得访问 GlueSight 数据目录 |
| 关于 | 应用名、版本、提交、构建时间、日志及数据位置 | 应用身份集中配置 |
| 工程入口 | 前端预览、桌面开发、定向测试、Windows 打包与基础 CI | 不依赖现场 SDK、算法引擎或本机绝对路径 |

默认页面建议为：欢迎/示例、设置、日志、关于。示例页展示如何注册一个业务页面，不接真实业务。

## 从现有代码抽取时的关键处理

- `src/layout/WindowFrame.tsx` 保留窗口行为，删除在线检测页面特判与 PLC、维护模式、引擎状态依赖。
- `src/layout/TitlebarContent.tsx` 的 details/actions 插槽可沿用；导航从 `Sidebar.tsx`、`nav.ts` 拆出业务入口和项目切换器。
- `src/App.tsx` 移除配方 `WorkspaceProvider`。`styles.css` 只提取布局与公共样式，避免带入业务选择器。
- `src/pages/SettingsPage.tsx` 借用布局和反馈方式；`src-tauri/src/settings.rs` 的 CycleSettings 是生产配置，不适合作为通用配置模型。
- `src/features/logs/` 保留日志浏览交互；抽走来自 PLC 模块的事件与时间工具，移除工件详情和历史跳转。
- `src-tauri/src/applog.rs` 的日志滚动与查询机制可以参考，但初始化仍依赖 ly-plc、视觉引擎和项目存储。通用版本需要独立的时钟、路径和上下文。
- `src-tauri/src/diagnostics.rs` 当前依赖生产历史、PLC、配方与原图。首版按通用日志导出需求重新组织。
- `src-tauri/src/fsio.rs` 和 `instance.rs` 可作为配置落盘、损坏备份与目录独占的参考；保存失败、并发保存和重启释放锁需定向验证。

## 模块组织建议

```text
src/
  app/                 应用身份、路由、导航与模块装配
  layout/              窗口、侧栏、页面容器与插槽
  features/
    settings/          通用设置
    logs/              日志浏览与导出
    about/             应用信息
    example/           可移除的业务页面示例
  lib/                 桌面调用、事件与时间工具
  styles/              公共主题及布局
src-tauri/src/
  app_info.rs          版本与构建信息
  config.rs            配置加载、校验和保存
  logging/             日志写入、查询、轮转和导出
  paths.rs             应用目录与环境隔离
  instance.rs          数据目录独占
docs/                  设计、契约与接入说明
scripts/               初始化、开发与打包
```

扩展先使用显式模块注册：页面、导航、设置区块和 React 插槽。Rust 命令显式注册。无需首版引入动态插件加载、通用依赖注入容器或独立插件协议。

业务模块依赖基础能力；基础能力不导入业务模块。桌面命令和事件通过统一基础层暴露，浏览器预览明确呈现后端不可用状态。

## 建议暂不进入基础模板

相机、PLC、lyFlow、配方与示教、检测历史、生产模拟器不属于通用范围。

多工作区/项目管理、SQLite 业务库、授权与账号、MCP、自动更新、后台任务中心作为待讨论能力，不默认纳入首版。若纳入，需先给出具体使用场景和独立的数据契约。

## 实施顺序与验收建议

1. 抽取可运行 UI 壳：无业务模块仍能启动，窗口控制、导航折叠、错误隔离和预览状态可用。
2. 打通设置与日志：设置重启后保留，保存失败不破坏原配置，并发保存不会静默覆盖；日志能写、查、翻页和受限清理，清理仅作用于本应用日志。
3. 完成模板初始化：名称、图标、包名、应用标识和数据目录可替换，两个生成应用互不读写对方数据。
4. 验证 Windows 开发与安装链路：依赖可从干净环境恢复，启动无需生产设备与算法运行库。

每个回归测试对应上述具体契约，实施前再列出实际用例。当前仓库只有文档，不声明运行、测试或打包通过。
